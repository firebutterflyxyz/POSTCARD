# 名片夾（網頁版 v1.1）

在手機上拍名片、自動辨識文字、核對後儲存；以公司、場合、分類、備註找人；把選定的名片打包成檔案交給同事。資料全部存在手機的瀏覽器裡，不上雲端。

---

## 一、技術選擇（摘要）

| 項目 | 做法 | 為什麼 |
|---|---|---|
| 形式 | PWA（可「加入主畫面」的網頁 App），純 HTML／CSS／JavaScript，不需編譯 | iPhone 與 Android 共用同一份程式，不需要 Mac、Xcode 或 App Store |
| 離線 | Service Worker 快取整個 App、辨識元件與模型 | 第一次有網路時開啟一次，之後飛航模式可用 |
| OCR | Tesseract.js 5（WebAssembly）＋繁體中文 `chi_tra`＋英文 `eng` 模型，**模型隨網站提供**（`tessdata/`） | 在手機瀏覽器內辨識，照片不離開手機 |
| 儲存 | IndexedDB，每位使用者一把隨機資料金鑰，名片、照片、分類一律 AES-256-GCM 加密 | 多使用者隔離；資料庫中沒有明文 |
| 登入 | 本機使用者名稱＋PIN；PIN 經 PBKDF2-SHA256（31 萬次）推導金鑰，用來解開資料金鑰，**PIN 本身不保存** | 不需要 Email、伺服器 |
| 名片包 | 單一 `.json` 檔，內含提供者、格式版本、名片識別碼（UUID）、勾選的欄位及照片（base64） | iPhone／Android 互通，接收者離線也能看照片 |
| 完整備份 | 單一 `.json` 檔，整份以備份密碼（PBKDF2＋AES-256-GCM）加密 | 換手機用；密碼錯誤不會動到現有資料 |

## 二、主要畫面

- **名片夾**：搜尋框（姓名、公司、職稱、電話、Email、分類、標籤、場合、備註、往來紀錄；電話忽略空格、括號、連字號）、可橫向滑動的分類篩選、排序（最近新增／依姓名／最近更新）、右上「選取」多選匯出。
- **拍名片**：點下去直接開相機；也可從相簿選或手動新增。拍完正面立即辨識；上方可切換正面／背面／大頭照並放大原圖，下方是可直接修改的欄位，有疑問的欄位標「請核對」並列出其他候選。辨識失敗可重試、手動輸入或存為「待整理」，照片保留。
- **名片詳情**：第一屏是姓名、公司、職稱、大頭照、「撥電話」「寄信」（多筆時先選）；往下依序是聯絡資訊、名片正反面、分類與標籤、認識資訊、固定備註、往來紀錄（倒序）、辨識原文。
- **我的**：目前使用者、鎖定、切換使用者、分類管理、匯入名片包、匯出 Excel（全部）、交給 Claude 辨識說明、建立完整備份、從備份還原、變更 PIN、離線辨識元件、儲存空間、刪除使用者。
- **匯出選單**（名片夾 → 選取 → 匯出…）：名片包（分享給同事）、Excel 表格、交給 Claude 辨識。

## 二之一、v1.1 新增

**Excel 匯出**：選取的名片或全部名片（「我的 → 匯出 Excel」）。全部欄位都會匯出，包含私人備註與往來紀錄，屬於自己使用的檔案。名片正反面放在同一格、上下排列，大頭照另一欄，照片直接嵌在儲存格裡。表頭凍結，可篩選。欄位順序集中寫在 `js/exporters.js` 的 `EXCEL_COLUMNS`，要調整順序或刪欄位，改那裡即可。

**交給 Claude 大量辨識**（內建辨識不理想時使用）：
1. 名片夾 → 選取 → 勾選名片（可先點「待整理」篩選）→ 匯出… → 交給 Claude 辨識 → 存下 zip。
2. zip 內有名片正反面照片、名片清單（含識別碼）以及「給Claude的說明.txt」。**不含**大頭照、私人備註、往來紀錄。
3. 把 zip 傳到 Claude 對話，說「請照說明辨識」。Claude 會回一個「名片包_Claude辨識_日期.json」。
4. 名片夾 → 我的 → 匯入名片包 → 選這個檔案。同一張名片會顯示「已存在・有更新」與新舊差異，**你手動改過的欄位預設保留你的版本**。按「匯入所選」後，原本「待整理」的名片會改為一般名片。

注意：使用這個功能時，名片照片會上傳到 Claude（Anthropic）。

## 三、部署到 GitHub Pages（只用網頁操作，不需要裝任何軟體）

1. 註冊／登入 GitHub，**開啟兩步驟驗證**（Settings → Password and authentication）。帳號被盜時，別人可以改掉網站程式，所以這一步很重要。
2. 右上「＋」→ **New repository**，名稱例如 `mingpianjia`，選 **Public**（免費帳號的 Pages 需要公開；公開的只有程式碼，沒有任何名片資料）→ Create。
3. 在新的 repository 頁面點 **uploading an existing file**，把這個資料夾裡的所有檔案和資料夾（`index.html`、`sw.js`、`manifest.webmanifest`、`package.json`、`css/`、`js/`、`icons/`、`tessdata/`、`tests/`、`README.md`）拖進去 → **Commit changes**。
4. `.github` 是隱藏資料夾，拖曳時常被略過。請改在 repository 頁面按 **Add file → Create new file**，檔名輸入 `.github/workflows/deploy.yml`，把本專案同名檔案的內容貼上 → Commit。
5. **Settings → Pages → Build and deployment → Source** 選 **GitHub Actions**。
6. 到 **Actions** 分頁，看到「部署名片夾到 GitHub Pages」跑完變綠色勾勾（約 1–2 分鐘）。它會先跑單元測試，再把辨識元件下載到同一網站。
7. 網址是 `https://你的帳號.github.io/mingpianjia/`。

之後要更新程式：上傳新檔案覆蓋即可，Actions 會自動重新部署。**每次更新請把 `sw.js` 第 2 行的 `VERSION` 改一個新值**（例如 `mpj-v1.0.1`），手機才會換成新版。

> 沒設定 Actions 也能用：網站會改從 jsDelivr CDN 下載辨識元件，並在第一次使用後快取。但 iPhone 上這種方式能否在飛航模式下辨識，需要實機確認，因此建議照上面第 4–5 步做。

## 四、安裝到手機

**iPhone（Safari）**：開網址 → 分享按鈕 → **加入主畫面** → 從主畫面圖示開啟。
一定要從主畫面開啟：iPhone 對「只在 Safari 分頁中使用」的網站，可能在一段時間沒用後清掉資料。

**Android（Chrome）**：開網址 → 右上「⋮」→ **安裝應用程式**（或「加到主畫面」）。
安裝後，在檔案管理員或 LINE 等 App 對名片包按「分享」，可以直接選「名片夾」匯入。

**第一次開啟後**：到「我的 → 離線辨識元件」點一下，等顯示「已就緒」，之後飛航模式也能辨識。

## 五、實機驗收步驟

準備：一支 iPhone、一支 Android，都已照第四節安裝並開過一次。

1. **飛航拍名片**：開飛航模式 → 拍名片 → 拍一張中英混排名片正面 → 點「＋背面」拍背面 → 確認兩面資訊都在同一筆（例如背面的手機、地址）→ 修正姓名 → 儲存 → 把 App 從背景完全關閉再開 → 輸入 PIN → 名片與照片仍在。
2. **快速儲存與補登**：拍名片 → 只拍正面 → 直接「儲存名片」→ 在詳情點「＋補拍大頭照」→ 編輯填「認識場合」→ 「新增往來」兩次 → 回名片夾，用場合或往來內容的關鍵字搜尋。
3. **使用者隔離**：我的 → 切換使用者 → 新增使用者 B → 確認清單、搜尋、選取匯出都看不到 A 的名片。
4. **跨系統分享**：A 選三張 → 匯出 → 不勾私人備註與大頭照 → 分享（例如透過 LINE、Email 或 AirDrop 傳到另一支手機）→ B 在另一種系統：我的 → 匯入名片包 → 只勾兩張 → 匯入 → 看得到正反面與「由 A 分享」。用電腦文字編輯器打開名片包，搜尋 A 的私人備註文字，應找不到。
5. **更新與共用總機**：A 改某張名片的分機 → 再分享給 B → B 匯入時看到「已存在・有更新」與新舊分機並排，自選要哪一個；B 原本自己寫的備註仍在。同公司兩位共用總機的同事，會被標為「可能重複」，預設「分開保留」。
6. **換手機**：A：我的 → 建立完整備份 → 設密碼 → 存檔 → 傳到新手機 → 新手機：建立使用者 → 從備份還原 → 先故意輸錯密碼（既有名片仍正常）→ 再輸入正確密碼 → 核對名片數量、照片、分類、備註、往來紀錄。

## 六、已實際測過的項目

測試環境：Linux 上的無頭 Chrome（模擬 390×844 手機、觸控、深色模式），以及 Node.js 22。

**單元測試**（`node --test tests/core.test.mjs tests/exporters.test.mjs`，17 項，全部通過）：電話正規化、各欄位搜尋、排序、首字顯示、OCR 文字分欄（使用真實 Tesseract 繁中＋英文辨識輸出）、正反面合併、重新辨識不覆蓋手動修改、名片包白名單（未勾選的資料與辨識原文不寫入）、損毀／不支援檔案、同識別碼／可能重複判定、合併後重複匯入不重複、往來紀錄去重與倒序、PIN 加密與錯誤 PIN、備份加解密與錯誤密碼、Excel 欄位順序與照片位置（正反面同格上下）、Claude 批次包內容、Claude 回傳結果的合併規則。

**端對端驗收**（`tests/e2e.mjs`，58 項，全部通過，重複執行皆穩定）：上面六個驗收情境，加上 v1.1 的 Excel 匯出與 Claude 辨識往返，包括：
- 離線（瀏覽器設為斷網）重新載入 App、建立使用者、拍正反面、儲存、重開後資料與照片仍在
- 辨識用的是**真正的 OCR**：測試時把 App 內實際處理後的照片交給本機 Tesseract（與網頁版相同的 `chi_tra`＋`eng` 模型）辨識，不是寫死的文字
- 切換使用者後畫面、搜尋、照片暫存都清空；資料庫裡讀不到明文；PIN 沒有明文
- 名片包檔案內容逐字檢查，沒有未勾選的資料
- 兩支「手機」用兩個獨立的瀏覽器設定檔模擬，透過實際檔案交換
- 損毀檔案匯入、錯誤備份密碼，名片庫都維持原狀
- 匯出的 Excel 以 openpyxl 讀取、以 LibreOffice 開啟檢查：欄位、內嵌照片數量、正反面同格上下
- 用 App 實際產生的 Claude zip，照裡面的說明辨識照片並產生名片包，再匯回 App，確認格式相符、差異比對正確

測試中找到並已修正的問題：還原到已有預設分類的新手機時，分類會重複；編輯畫面底部條件按鈕會顯示「null」字樣。

## 七、仍需實機確認的項目

這些在測試環境無法驗證，請依第五節在真手機上確認：

- **網頁版 Tesseract 的辨識品質與速度**。邏輯已用同一套模型驗證，但手機上的 WebAssembly 效能（預估每面 5–20 秒）、實際拍攝的反光、歪斜、小字都要實測。
- **iPhone 飛航模式下的辨識**：需先完成第三節的 Actions 部署（辨識元件放在同一網站），並在「我的 → 離線辨識元件」顯示已就緒。
- 手機相機直接開啟（`拍名片` 點下去）、從相簿選圖、HEIC 照片轉檔。
- 系統分享選單（iPhone 分享表單、Android 分享）與「儲存到檔案」。
- Android「從其他 App 分享名片包給名片夾」（share target）。**iPhone 不支援由檔案 App「用名片夾打開」**，只能從「我的 → 匯入名片包」選檔。
- 撥電話（含分機自動撥號）、寄信連結。
- 加入主畫面後的長期資料保存（iPhone 的清除政策）、自動鎖定（離開 5 分鐘後回來需重新輸入 PIN）。
- 大量名片（數百張以上）時的速度與備份檔大小（每張照片約 200–400 KB）。
- Excel 在手機上的開啟效果（電腦版 Excel 與 LibreOffice 的照片位置已確認，手機版 Excel／Numbers 可能略有差異）。
- 一次交給 Claude 的張數上限：取決於 Claude 對話一次能處理的照片數量，建議每批 20–30 張以內。

## 八、和原生 App 規格的差異（網頁版限制）

- **金鑰保管**：網頁無法使用 iPhone Keychain／Android Keystore。改以 PIN 推導的金鑰加密資料金鑰，安全性取決於 PIN 長度。建議用 6 位以上 PIN，錯誤 5 次會暫時鎖定。
- **生物辨識**：第一版未提供（已確認）。
- **OCR 準確度**：低於手機原生辨識（Apple Vision／Google ML Kit），比較常需要人工核對。辨識原文會保留，點任一行可以直接填入欄位。
- **資料存在瀏覽器**：清除 Safari／Chrome 網站資料會一併刪除名片。請定期建立完整備份。

## 九、檔案結構

```
index.html              App 外殼（含內容安全政策）
sw.js                   Service Worker：離線快取、Android 分享匯入
manifest.webmanifest    PWA 設定（圖示、分享目標）
css/app.css             介面樣式（自動跟隨淺色／深色模式）
js/core.js              核心邏輯：搜尋、OCR 分欄、名片包、匯入比對與合併
js/exporters.js         Excel 匯出（含照片）與交給 Claude 的批次包；Excel 欄位設定
js/vendor/jszip.min.js  JSZip 3.10.1（MIT），產生 xlsx／zip
js/crypto.js            加密：PIN、資料金鑰、完整備份
js/db.js                IndexedDB 加密儲存、多使用者
js/ocr.js               手機端 OCR（Tesseract.js）
js/ui.js                介面元件
js/app.js               畫面與流程
tessdata/               繁體中文與英文辨識模型
icons/                  App 圖示
tests/                  單元測試與端對端測試
.github/workflows/      GitHub Pages 自動部署
```

## 十、開發者用：在電腦上跑測試

```bash
node --test tests/core.test.mjs tests/exporters.test.mjs   # 單元測試（Node 18+）
python3 -m http.server 8765              # 本機預覽 http://localhost:8765
node tests/e2e.mjs                       # 端對端測試（需 Playwright、Chrome、tesseract＋chi_tra）
```
